# LEAN Triage Engine (LTE)：MRAP形式による超軽量・高精度トリアージ・インフラの仕様
**— 論文・主張の「意味」ではなく「構造と数式」をパースし、次元・熱力学・因果律ゲートでスパム・破綻ロジックを0.1秒で弾き出すフロントエンド・ゲートキーパー —**

## 1. Abstract（概要）
AIや人間が提出する膨大な論文、事業計画、技術的主張（テキスト）を精査する際、自然言語の文脈や権威的な自己紹介（ポエム）に惑わされず、数理的・物理的妥当性を高速でトリアージするインフラとして **`LTE (LEAN Triage Engine)`** を定義する。

本エンジンは、入力データを機械可読な統一プロトコル **`MRAP (Machine-Readable Academic Protocol)`** に強制変換させ、内部の「アトラクティア・ライト（3大数理ゲート）」によって永久機関的ロジックや論理の循環を数理レベルで足切りする。さらに、数理化できない非線形変数（人間の心理や社会的コンセンサス）を含む場合は自動的に「エスケープハッチ」を発動して人間へ委譲する など、現実的かつ堅牢な査読・格付けパイプラインを構築する。

## 2. Input Protocol：MRAP (Machine-Readable Academic Protocol)
ユーザー（AIエージェントまたは人間）は、自然言語の冗長性を排除した以下のJSONライクなブロック構造（MRAP形式）で主張をエントリーしなければならない。エントリポイントにおいて、文字装飾や権威的自己紹介は強制パージされる。

```json
{
  "source": "観測事実、初期値、前提となる既知の変数定義（例: x = チームのエネルギー状態）",
  "premise": "論理を展開するための前提条件、依拠する物理・数学の基本式",
  "core_dag": "主張の中核となる因果の矢印（例: A -> B -> C の関数関係）",
  "conclusion": "帰結、およびそれによって導かれる予測値、問いかけ",
  "stake_proof": "Mantleテストネット等でのトークンステーク証明（ボットスパム防止用ハッシュ）"
}
```

## 3. Internal Audit Core：アトラクティア・ライト（3大数理ゲート）
MRAP形式でパージされた数式オブジェクトに対し、アトラクティア・ライトは以下の3つの監査ゲートを逐次適用する。

### ① 次元・熱力学ゲート (Dimension & Entropy Gate)
* **処理：** 数式の左辺と右辺の次元（物理単位）の整合性を確認する。また、孤立系においてエントロピーが減少するような「永久機関的ロジック（$dS < 0$）」や、熱力学第二法則に反する可逆反転が含まれていないかを一瞥で足切りする。
* **判定：** 違反が確定した場合は即座に `REJECTED`（即時破棄・ステーク没収）へルーティングする。

### ② 因果律グラフ監査 (Causality DAG Auditor)
* **処理：** `core_dag` のテキストを純粋な有向非巡回グラフ（DAG）に変換し、論理のループ（AだからB、BだからA）や、熱力学的不可逆性に逆行する因果関係（過去への遡行）を検知する。
* **判定：** 循環参照や未閉鎖の因果が検出された場合も `REJECTED` とする。

### ③ トラスト・スコア・ルーター (Trust Scorer & Router)
* **処理：** 物理則や数式で完全に計算しきれない「非線形な変数（人間の心理、欲望、社会的コンセンサス等）」のブラックボックス割合を算出する。
* **判定：** 数理的確実性（Trust Score）が **90%未満** の場合、AI単体での断定を停止し、自動的にエスケープハッチを発動する。

## 4. Output Specification：格付け（Tier）とルーティング
監査を通過したデータは、その厳密性に応じて以下の4段階に格付け（Tier）され、出力・パブリッシュされる。

| 格付けステータス | 対象・条件 | 処理・ルーティング |
| :--- | :--- | :--- |
| **Tier 0 〜 Tier 2** | 物理則・数理的整合性の監査を完全にクリアした堅牢な主張・論文。 | Hugging Face Spaces上に格付けタグ付きで自動パブリッシュ。 |
| **Tier 3 (エスケープハッチ)** | 内部の論理や因果は通っているが、数理化できない「人間要素（ブラックボックス変数）」を含むもの。 | 自動判定を停止し、人間の査読者（Master）へルーティング。 |
| **REJECTED** | 次元・熱力学・因果律のいずれかの破綻が数理的に確定したもの。 | 即時破棄。提出者のステーク（トークン）をボットの稼働費として没収。 |

## 5. Deployment Roadmap（Hugging Face公開までの最短ビルドフロー）
パースのハルシネーションやUI設計の破綻を防ぐため、以下の順序（シーケンス）を厳守してビルドを執行する。

1. **Step 1：MRAPパーサーの構築（ローカル / Antigravity）**
   * ユーザーが入力した自然言語のテキストブロックから、変数（Variables）と因果の矢印（DAG）を、正規表現と軽量SLMを用いて純粋な「数式オブジェクト」として抽出するPythonスクリプトを実装する。
2. **Step 2：3大監査ゲート（アトラクティア・ライト）の実装**
   * 抽出された数式オブジェクトに対し、①次元解析チェック、②グラフの循環検知、③エントロピー増大則バリデーターを実装し、ジャンクデータを0.1秒で弾く電卓エンジンを完成させる。
3. **Step 3：トラスト・スコアとエスケープハッチのロジック固定**
   * ブラックボックス変数の割合算出アルゴリズムを組み込み、信頼度90%未満のデータを自動的に「Tier 3（人間委譲）」へ振り分けるルーターをプログラミングする。
4. **Step 4：Hugging Face SpacesへのUIデプロイ**
   * Gradio等の軽量フレームワークを用い、左側に「MRAP論文入力フォーム」、右側に「リアルタイム因果律DAGグラフ」と「格付けティアバッジ（Tier 0〜3 / REJECT）」が表示されるWeb UIを構築し、HFへデプロイする。
